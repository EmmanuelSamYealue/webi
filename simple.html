Module 1: Web Basics

Think of it like this: the Internet is the road network. The Web is the trucks that deliver packages on those roads. They are not the same thing.

1.1 The Internet and the Web

The Internet is the wires, routers, and rules that connect computers around the world.

The Web is the pages you open in a browser. Those pages travel over the Internet.

Email also uses the Internet. But email is not the Web. The Web is just one service on the Internet.

In short: Internet = the roads. Web = the trucks on the roads.

1.2 Browser and server

A browser is the program you open pages with. Chrome, Firefox, Edge, and Safari are browsers.

A server is a computer somewhere in the world that keeps the pages.

When you open a page, your browser asks a server for it. The server sends it back.

This is called the client–server model. The browser is the client. The server is… the server.

1.3 What happens when you open a page

You type example.com. Here is what happens, in order:

  1. Your browser reads the address.
  2. It asks a service called DNS for the server's real number. DNS is like a phone book.
  3. It connects to that server.
  4. It says: “please send me this page”.
  5. The server replies with the page — usually an HTML file.
  6. The browser reads the page. It sees the page needs CSS, images, and JavaScript, so it asks for those too.
  7. The browser builds the page and draws it on screen. This is called rendering.
  8. JavaScript runs and the page becomes alive (buttons respond, and so on).

1.4 What is a URL?

A URL is a web address. Every part has a job.

PartExampleWhat it means
Protocolhttps://How to send the files. HTTPS is encrypted.
Domainwww.bcu.edu.lrThe name of the server.
Path/aboutWhich page on the server.
Query?id=5Extra information.
Fragment#teamJump to a section on the same page.

1.5 Three languages make a page

LanguageJobThink of it as…
HTMLThe structure and contentThe skeleton
CSSThe colors, fonts, and layoutThe skin and clothes
JavaScriptThe actions (clicks, changes)The muscles

These three are always kept in separate files. This is called separation of concerns. It makes the site easier to change, share, and fix.

1.6 Static sites and dynamic sites

A static site sends the same pages to every visitor. Fast, cheap, and safe. Good for portfolios and small business sites.

A dynamic site builds pages on the spot. It can have user accounts, search, and shopping carts. Needs more work and more security.

1.7 Build in this order

  1. HTML first — make a working page.
  2. CSS second — make it look good.
  3. JavaScript third — make it react.

This is called progressive enhancement. If JavaScript fails, the page still shows the content.

1.8 Who decides the rules?

  • WHATWG — maintains the HTML standard.
  • W3C — publishes CSS and accessibility rules.
  • ECMA — standardises JavaScript.
  • IETF — publishes HTTP and Internet standards.

These are independent bodies, not one company. That is why every browser works roughly the same way.

Try it

Open any website. Press F12 to open DevTools. Click the Network tab. Reload (F5). You will see every file the browser asked for — the request cascade live.

Module 2: How a Website is Made

Think of it like this: a website is a folder of files, not one big file. The browser opens each file and puts the page together.

2.1 The folder

my-website/
├── index.html          (the home page)
├── about.html          (another page)
├── css/
│   └── style.css       (the styles)
├── js/
│   └── script.js       (the actions)
├── images/
│   └── logo.png
└── fonts/
File / FolderWhat it is
index.htmlThe page the server sends when you visit a folder address. Always name your home page this.
about.htmlAnother page.
css/style.cssOne stylesheet shared by every page.
js/script.jsOne JavaScript file shared by every page.
images/All pictures.
fonts/Custom fonts.
Rule: use lowercase names with hyphens, never spaces. my-photo.jpg works. my photo.jpg can cause errors.

2.2 A basic home page

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Home | My Portfolio</title>
    <link rel="stylesheet" href="css/style.css">
</head>
<body>
    <header>
        <h1>My Portfolio</h1>
        <nav>
            <a href="index.html">Home</a>
            <a href="about.html">About</a>
        </nav>
    </header>
    <main>
        <h2>Welcome</h2>
        <p>This is my portfolio.</p>
    </main>
    <footer>
        <p>&copy; 2025 My Name</p>
    </footer>
    <script src="js/script.js" defer></script>
</body>
</html>

2.3 The CSS file

*, *::before, *::after { box-sizing: border-box; }

body {
    margin: 0;
    font-family: system-ui, Arial, sans-serif;
    line-height: 1.6;
}

header {
    background: #1a365d;
    color: white;
    padding: 1rem 2rem;
}

nav a {
    color: white;
    text-decoration: none;
    margin-right: 1rem;
}

main {
    max-width: 900px;
    margin: 2rem auto;
    padding: 0 1rem;
}

2.4 The JavaScript file

<script src="js/script.js" defer></script>

The defer word means “download it in the background, then run it after the page is fully read”.

2.5 How the browser loads everything

  1. Asks for index.html.
  2. Starts reading it and building the page.
  3. Finds the CSS link, so asks for the CSS file. CSS blocks the first drawing, so the page does not flash without styles.
  4. Finds image tags, so asks for images. Images do not block drawing.
  5. Finds the script, so downloads it. Runs it after the HTML is fully read.
  6. Draws the page. This is called rendering.

2.6 What happens if you remove one layer

RemoveWhat happensWhat it teaches
CSSPage still works, but looks plain.CSS is presentation only.
JavaScriptContent shows, but buttons do nothing.JavaScript is an enhancement.
HTMLNothing displays.HTML is the foundation.

Try it

Make a folder called my-website. Inside it make css and js folders. Create index.html using the code above. Create css/style.css. Open index.html. Open DevTools → Console. If you see “Failed to load resource”, a path is wrong — usually a typo.

Module 3: Page, Site, App, Software — What is the Difference?

Think of it like this: a web page is one sheet of paper. A website is a whole book. A web app is an interactive workbook. Software is every published work in the world. An application is one specific tool, like a calculator.

3.1 Web page

One single HTML document. It has its own URL. Example: about.html.

3.2 Website

A group of related pages under one domain, sharing navigation and design. Example: bcu.edu.lr.

3.3 Web app

A website that behaves like software. It saves data, has user accounts, and does tasks. Example: Gmail, Google Docs, online banking.

3.4 Software

Any set of instructions that tells a computer what to do. This is the broadest word. Example: Windows, Photoshop, Chrome.

3.5 Application (app)

A program made for one specific task. Every app is software. Not every software is an app — an operating system is software but not an app.

3.6 The comparison

WordSizeIn a browser?Saves data?Example
Web pageOne documentYesNoabout.html
WebsiteMany pagesYesMinimalbcu.edu.lr
Web appInteractiveYesYesGmail
SoftwareAny programSometimesDependsWindows
ApplicationSoftware for one taskSometimesDependsMS Word

Rule of thumb: if the main purpose is to read, it is a website. If the main purpose is to do something with data, it is a web app.

Try it

Decide what each one is: an about.html file (a web page), a school's whole domain (a website), Gmail (a web app), Windows (software), and MS Word (an application). Say your answer out loud — explaining it is the best way to remember.

Module 4: How the Web Has Changed

Think of it like this: Web 1.0 is a poster you can only read. Web 2.0 is a poster that everyone can write on. Web 3.0 is a poster that you can prove belongs to you.

4.1 Web 1.0 — read only (1991 to about 2004)

Early sites were like printed brochures. Only the owner could put content up. Visitors could only read.

  • Static HTML pages.
  • No comments, likes, or user accounts.
  • Slow dial-up internet.

Examples: the early Yahoo directory, GeoCities personal pages, simple company sites.

4.2 Web 2.0 — read and write (about 2004 to now)

Users started writing the content. Social media, wikis, video platforms, and comment sections were born.

  • User posts, likes, shares, follows.
  • Pages update without a reload (AJAX).
  • A few big companies own the data.
  • Responsive design and mobile-first thinking.

Examples: Facebook, YouTube, Wikipedia, Google Docs.

4.3 Web 3.0 — read, write, and own (emerging)

An emerging stage where users own their own data, often using a technology called blockchain.

  • No single company controls the app.
  • Built on blockchain and smart contracts.
  • Users own their identity and digital items.

Examples: Ethereum apps, NFTs, DeFi exchanges.

4.4 The comparison

GenerationEraWho creates content?Who owns data?
Web 1.01991–2004PublishersPublishers
Web 2.02004–nowUsers and platformsPlatforms
Web 3.0EmergingUsersUsers (blockchain)

4.5 What is blockchain?

A blockchain is a shared record book. Many computers keep a copy at the same time. Once something is written in the book, nobody can quietly change it — because every copy must agree.

How a payment works, in simple steps:

  1. Someone asks to send money from Alice to Bob.
  2. The request goes to thousands of computers.
  3. Each computer checks the rules — does Alice really have the money?
  4. Valid payments are grouped into a block.
  5. Each block is mathematically linked to the one before it, forming a chain.
  6. Every computer updates its copy. Changing one block would break every block after it.

4.6 What blockchain is used for

UseExample
Digital moneyBitcoin, Ether
Smart contractsEthereum agreements that run automatically
NFTs (digital ownership)Digital art marketplaces
Supply chain trackingWalmart food tracking
Digital identityMicrosoft ION
Land recordsGeorgia (the country)
DiplomasMIT Blockcerts

4.7 Blockchain limits

  • Slow and expensive compared to a normal database.
  • No undo. Send money to the wrong address, and it is gone.
  • Scams. Many “blockchain” products are ordinary databases with a fancy label.
  • Not always needed. If a normal database does the job, use that.

Try it

Name three sites you use every day. Say which Web generation they belong to and why in one sentence each.

Module 5: HTML Basics

Think of it like this: HTML is a set of labels you stick on different parts of a page. “This is a heading.” “This is a paragraph.” “This is a picture.” The browser reads the labels and shows the page correctly.

5.1 What is HTML?

HTML stands for HyperText Markup Language.

It is not a programming language. It has no maths and no logic. It only labels parts of the page.

5.2 Tags and elements

A tag is a label in angle brackets, like <p>.

An element is a tag, its content, and its closing tag.

<p>Hello, world!</p>
  • <p> is the opening tag.
  • Hello, world! is the content.
  • </p> is the closing tag.

5.3 Tags with no closing

Some tags have nothing inside. They have no closing tag.

<br>
<img src="cat.jpg" alt="A cat">

These are called void elements.

5.4 Nesting

Elements can go inside other elements. But you must close the last one first.

Wrong: <p><strong>text</p></strong>
Right: <p><strong>text</strong></p>

5.5 Every page starts like this

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <meta name="description" content="A short summary for search engines.">
    <title>My First Page</title>
    <link rel="stylesheet" href="css/style.css">
</head>
<body>
    <h1>Welcome</h1>
    <p>This is my first page.</p>
    <script src="js/script.js" defer></script>
</body>
</html>
LineWhat it means
<!DOCTYPE html>“This is a modern HTML page.” Without it, browsers behave differently.
<html lang="en">The whole page, in English.
<head>Info about the page — not shown.
<meta charset="UTF-8">Lets you use letters like é, ñ, ẹ.
<meta name="viewport" ...>Makes phones use their real width.
<title>Name on the browser tab.
<link rel="stylesheet">Loads the CSS file.
<body>Everything visitors see.

5.6 Common attributes

Attributes go on the opening tag. They always look like name="value".

AttributeUse
idOne unique name per page.
classReusable labels for styling.
titleTooltip on hover.
hiddenHides the element.
langLanguage of the content.

5.7 Comments and spaces

<!-- This is a comment. Visitors cannot see it. -->

Many spaces and line breaks in your code become a single space on the page. That is why <br> and <pre> exist.

Warning: never put passwords in HTML comments. Anyone can view the page source.

Try it

Type the skeleton above by hand into index.html. Change the <title> and reload — the tab changes. Change the <h1> and reload — the page changes. You have just learned the difference between <head> and <body>.

Module 6: Text and Headings

Think of it like this: headings are the chapter titles of a book. They tell the reader what each section is about. Paragraphs are the sentences underneath.

6.1 Headings

There are six heading levels: <h1> (most important) to <h6> (least).

<h1>Main title</h1>
<h2>Section</h2>
<h3>Smaller section</h3>
  • Use one <h1> per page.
  • Do not skip sizes — go h1 → h2 → h3.
  • Use CSS to make headings bigger. Do not pick a tag just because it looks big.

6.2 Paragraphs

<p>This is a paragraph.</p>
<p>This is another.</p>

The browser puts a gap between paragraphs automatically.

6.3 Block and inline

  • Block elements start on a new line. They take the full width. Example: <p>, <h1>, <div>.
  • Inline elements stay inside the line. Example: <strong>, <a>, <span>.

6.4 Bold, italic, and meaning

TagLooks likeUse for
<strong>boldSomething important
<b>boldAttention (no extra importance)
<em>italicStress on a word
<mark>highlightedText you want to point at
<small>smallFine print
<code>codeComputer code
<abbr>HTMLShort forms

Tip: choose tags for the meaning. Then use CSS to change how they look.

6.5 Line breaks and dividers

<p>John Doe<br>
Main Street 12<br>
Monrovia</p>

<hr>

<br> breaks a line inside a paragraph. <hr> draws a divider (a break between sections).

6.6 Special characters

Some characters are reserved. Write them with a character reference.

CodeShowsWhy you need it
&lt;<Otherwise HTML thinks a tag starts.
&gt;>Closes a tag.
&amp;&Otherwise HTML thinks a code starts.
&copy;©Copyright sign.
&nbsp; Space that does not break a line.

Try it

Make a page with one <h1>, two <h2> sections, and a paragraph under each. Bold one word in each paragraph and italicise another.

Module 7: Links and Images

Think of it like this: a link is a door to another page. An image is a picture you hang on the wall. Both use a tag, both need a file path.

7.1 Links

<a href="about.html">About me</a>
<a href="https://example.com">Visit Example</a>
<a href="mailto:info@example.com">Email us</a>
<a href="tel:+231770000000">Call us</a>
AttributeWhat it does
hrefThe destination address.
target="_blank"Opens in a new tab (add rel="noopener" for safety).

Write clear link text. “Read the admission rules” is better than “click here”.

7.2 Types of link

TypeExample
Full addresshttps://example.com/about
In the same folderabout.html
One folder up../images/logo.png
Same page, specific place#timetable
Emailmailto:info@example.com

7.3 Images

<img src="images/library.jpg"
     alt="Students studying in the library"
     width="800" height="500">
AttributeWhat it does
srcThe image file path. Required.
altText description. Shows if the image fails to load. Read by screen readers.
width, heightSpace kept for the image before it loads.

Writing good alt text

  • Informative: describe what matters. “Bar chart showing enrolment rising from 120 to 310.”
  • Decorative: use alt="" so screen readers skip it.
  • Inside a link: describe where the link goes.
  • Do not start with “Image of…”.

7.4 Figure and caption

<figure>
    <img src="images/diagram.png" alt="Diagram of a client asking a server">
    <figcaption>Figure 1: The client-server cycle.</figcaption>
</figure>

7.5 Video and audio

<video src="media/lecture.mp4" controls width="640">
    Your browser does not support video.
</video>

<audio src="media/announcement.mp3" controls>
    Your browser does not support audio.
</audio>

controls adds play buttons. Without it, the media cannot be used. Autoplay is blocked by most browsers — do not use it.

7.6 Iframes

An <iframe> puts another page inside your page — useful for maps and video embeds.

<iframe src="https://www.openstreetmap.org/..."
        title="Map of the university" width="600" height="400">
</iframe>

Try it

Add one image and one link to your page. Break the image filename on purpose and reload — you should see the alt text. That is why alt matters.

Module 8: Lists and Tables

Think of it like this: a list is a shopping list. A table is a timetable. Lists have items. Tables have rows and columns.

8.1 Bullet lists

<ul>
    <li>HTML</li>
    <li>CSS</li>
    <li>JavaScript</li>
</ul>

ul means “unordered list”. The order does not matter.

8.2 Numbered lists

<ol>
    <li>Boil water</li>
    <li>Add tea</li>
    <li>Wait three minutes</li>
</ol>

ol means “ordered list”. The order matters.

8.3 Word lists

<dl>
    <dt>DOM</dt>
    <dd>The browser's live model of the page.</dd>
</dl>

Use when you have a word and its meaning.

8.4 Lists inside lists

<ul>
    <li>Front-end
        <ul>
            <li>HTML</li>
            <li>CSS</li>
        </ul>
    </li>
</ul>

A nested list goes inside an <li>, never directly inside the <ul>.

8.5 Tables

Tables are for data — rows and columns where the relationships matter. Tables are not for page layout.

<table>
    <caption>Course timetable</caption>
    <thead>
        <tr>
            <th scope="col">Course</th>
            <th scope="col">Day</th>
        </tr>
    </thead>
    <tbody>
        <tr>
            <th scope="row">Web Design</th>
            <td>Monday</td>
        </tr>
    </tbody>
</table>
TagMeaning
<table>The whole table.
<caption>A title for the table.
<tr>One row.
<th>A header cell.
<td>A normal data cell.

Try it

Make one page with a numbered recipe and one page with a small 3×3 table of your class timetable. Add scope="col" to every header cell.

Module 9: Meaningful HTML

Think of it like this: you could put everything in a plain box, but it would be hard to find anything. Meaningful tags are labelled boxes — one for the header, one for the menu, one for the main content.

9.1 The main parts of a page

TagWhat goes inside
<header>The top — site name and logo.
<nav>The menu of links.
<main>The main content. Only one per page.
<section>A block of related content.
<article>A self-contained item (a blog post, a news story).
<aside>A sidebar or related links.
<footer>The bottom — copyright, contact.
<div>A generic box. Use only when no other tag fits.

9.2 Example

<body>
    <header>
        <h1>My School</h1>
        <nav>
            <a href="index.html">Home</a>
            <a href="about.html">About</a>
        </nav>
    </header>

    <main>
        <section>
            <h2>Latest news</h2>
            <article>
                <h3>New lab opens</h3>
                <p>Thirty workstations are available.</p>
            </article>
        </section>
    </main>

    <footer>
        <p>&copy; 2025 My School</p>
    </footer>
</body>

9.3 Why it matters

  1. Screen readers can jump straight to the main content.
  2. Search engines can tell what the article is and what the sidebar is.
  3. You can read the code and understand it months later.

9.4 ARIA — when HTML is not enough

ARIA adds extra info for screen readers when HTML cannot describe something — for example a custom tab widget.

<div role="alert">Your changes were saved.</div>
First rule of ARIA: do not use ARIA if a normal HTML tag already does the job. A real <button> is better than <div role="button">.

Try it

Take the page you built in Module 6 and wrap it in <header>, <main>, and <footer>. Wrap the links in <nav>. Nothing looks different — but the page is now much better for screen readers.

Module 10: CSS Basics

Think of it like this: HTML builds the house. CSS paints and decorates it. Every CSS rule says “find this thing and change this about it”.

10.1 A CSS rule

h1 {
    color: blue;
    font-size: 32px;
}
  • h1 — the selector. Who to style.
  • color: blue; — a declaration. What to change.
  • color — the property.
  • blue — the value.
  • ; — the semicolon ends each declaration. Forgetting it breaks the CSS.

10.2 Three ways to add CSS

WayExampleGood?
Inline<p style="color: red">Rarely. Cannot reuse.
Internal<style> p { color: red } </style>Small single pages.
External<link rel="stylesheet" href="style.css">Best. One file styles the whole site.

10.3 Which rule wins?

When two rules set the same thing, the browser decides a winner. Three ideas:

  1. Order: later rules beat earlier rules.
  2. Inheritance: some properties (like colour) pass from parent to child automatically.
  3. Specificity: more specific selectors beat less specific ones.
SelectorScoreExample
Inline style1000style="..."
ID100#title
Class10.notice
Tag1p

10.4 Common selectors

p { }               /* every paragraph */
.notice { }         /* class="notice" */
#title { }          /* id="title" */
nav a { }           /* links inside a nav */
a:hover { }         /* link while mouse is on it */

10.5 CSS variables

Save a value once, use it everywhere:

:root {
    --brand: #2b6cb0;
    --space: 1rem;
}

.button {
    background: var(--brand);
    padding: var(--space);
}

Change --brand once and every button updates.

Try it

Create css/style.css and link it. Give h1 a colour, body a font, and a a hover effect. Reload and watch the whole page change without touching the HTML.

Module 11: Colors and Fonts

Think of it like this: colour and font are the mood of the page. Dark blue feels calm. Bright red feels urgent. A serif font feels formal. A sans-serif font feels modern.

11.1 Colours

WayExample
Namered, tomato
Hex#2b6cb0
RGBrgb(43, 108, 176)
HSLhsl(210, 60%, 43%)

11.2 Contrast

Contrast means how easy it is to tell text from the background.

  • Body text: at least 4.5 to 1.
  • Large text: at least 3 to 1.
  • Very readable: 7 to 1.
Never rely on colour alone. An error must have text or an icon, not just a red border. About 1 in 12 men is colour blind.

11.3 Fonts

body {
    font-family: system-ui, Arial, sans-serif;
    font-size: 16px;
    line-height: 1.6;
    color: #24313d;
}
  • font-family — the font name. End with sans-serif or serif as a fallback.
  • font-size — the text size.
  • line-height — space between lines. 1.4 to 1.6 is comfortable.

11.4 Units

UnitRelative toUse for
pxA fixed pixelBorders
remThe root font sizeFonts and spacing. The safest default.
emParent font sizePadding inside one component
%Parent's valueWidths
vw / vh1% of the screen width / heightBig banner sections

Why rem matters: if a visitor increases their browser's font size for readability, layouts built with rem grow with it. Layouts built only with px do not — that is unfair to them.

Try it

Change your body font to Georgia, serif and your headings to Verdana, sans-serif. Then change the body font size to 1.05rem. Notice how everything scales together.

Module 12: The Box Model

Think of it like this: every element on the page is a parcel. Inside is the content. Around it is padding (the cushion). Then the box itself is the border. Then margin is the empty space between this parcel and the next one on the shelf. 
+----------------------------+   <-- margin (space outside)
|  +----------------------+  |
|  |  border              |  |
|  |  +----------------+  |  |
|  |  |  padding       |  |  |
|  |  |  +----------+  |  |  |
|  |  |  | CONTENT  |  |  |  |
|  |  |  +----------+  |  |  |
|  |  +----------------+  |  |
|  +----------------------+  |
+----------------------------+
LayerWhat it is
ContentThe text or image inside.
PaddingSpace inside the border. Cushion.
BorderA visible line.
MarginSpace outside. Pushes other boxes away.

12.1 box-sizing

* {
    box-sizing: border-box;
}

Without this, a box with width: 200px and padding: 20px actually takes up 240px. With border-box, the width stays exactly 200px. Almost every project starts with this line.

12.2 Display

ValueWhat it does
blockNew line, full width.
inlineStays inside the line.
noneRemoves the element completely.
flex / gridBecomes a flex or grid container (Module 13).
display: none vs visibility: hidden: display: none removes the box entirely. visibility: hidden hides it but keeps the space.

12.3 Positioning

ValueWhat it does
staticNormal flow (default).
relativeStays in flow but can be nudged.
absoluteRemoved from flow; pinned to a positioned parent.
fixedStays in place when scrolling.
stickyScrolls, then sticks when it hits a threshold.

12.4 Overflow

.scroll-area {
    max-height: 300px;
    overflow-y: auto;
}

auto adds scrollbars only when needed. hidden clips whatever does not fit.

Try it

Make a <div> with padding: 20px; border: 5px solid red; margin: 30px; background: #eee;. Open DevTools → Elements and hover the element. The browser draws the coloured box model right on the page. Then add box-sizing: border-box; and set width: 200px — watch the total width stay exactly 200px.

Module 13: Flexbox and Grid

Think of it like this: Flexbox arranges things in one line — like seats in a row. Grid arranges things in rows and columns — like tiles on a floor.

13.1 Flexbox

.menu {
    display: flex;
    gap: 1rem;
    justify-content: space-between;
    align-items: center;
    flex-wrap: wrap;
}
PropertyWhat it does
flex-directionRow (default) or column.
justify-contentSpaces items along the row.
align-itemsCentres them across the row.
gapSpace between items.
flex-wrapAllows items onto new lines when tight.

13.2 Grid

.gallery {
    display: grid;
    grid-template-columns: 1fr 1fr 1fr;
    gap: 15px;
}

1fr means “one share of the free space”. Three of them make three equal columns.

13.3 A ready-made responsive grid

.cards {
    display: grid;
    grid-template-columns: repeat(auto-fit, minmax(220px, 1fr));
    gap: 15px;
}

This one line makes as many columns as will fit, each at least 220px wide. One column on a phone, three or four on a desktop. No media queries needed.

13.4 When to use which

Use Flexbox when…Use Grid when…
Items go in one directionYou need rows and columns
Navigation bars, toolbarsGalleries, page layouts
You want to centre somethingYou want exact placement

They combine well: use Grid for the page skeleton, Flexbox inside each component.

Try it

Make six <div> boxes with different background colours. Wrap them in a container with the repeat(auto-fit, minmax(220px, 1fr)) grid. Resize the browser — the boxes rearrange themselves.

Module 14: Responsive Design

Think of it like this: responsive means your page fits every screen — phone, tablet, laptop. One page, many sizes.

14.1 The viewport tag

Put this in the <head> of every page:

<meta name="viewport" content="width=device-width, initial-scale=1.0">

Without it, phones pretend to be desktops and everything looks tiny. Never add user-scalable=no — that prevents zoom, which is unfair to people who need it.

14.2 Mobile-first

Start by writing styles for a phone. Then add rules for bigger screens.

/* Phone */
.grid { grid-template-columns: 1fr; }

/* Tablet and up */
@media (min-width: 700px) {
    .grid { grid-template-columns: 1fr 1fr; }
}

/* Desktop and up */
@media (min-width: 1000px) {
    .grid { grid-template-columns: 1fr 1fr 1fr; }
}

14.3 Images and width

img {
    max-width: 100%;
    height: auto;
}

This makes images shrink to fit their container instead of overflowing.

14.4 Testing

  • Open DevTools (F12) and click the phone icon to emulate a small screen.
  • Try 320px, 375px, 768px, 1024px, and 1440px.
  • Check that no box overflows.
  • Buttons should be at least 44×44 pixels for finger taps.

Try it

Open any of your pages. Press F12 → phone icon. Try 320px wide. Does anything overflow? If yes, add max-width: 100% to images and check any boxes with fixed widths. Fix them one by one.

Module 15: Forms

Think of it like this: a form is a paper form you fill in. You write your name, tick boxes, and hand it back. A web form works the same way — the browser collects the answers and sends them to the server.

15.1 The form tag

<form action="/submit" method="post">
    ...
</form>
AttributeWhat it does
actionWhere the answers go.
methodget puts answers in the URL (good for search). post hides them (use for anything private).
Never use GET for passwords. The answers show up in the URL, browser history, and logs.

15.2 Labels

Every input must have a label. A label tells users what to type. Clicking the label focuses the input.

<label for="email">Your email</label>
<input id="email" name="email" type="email">

The for on the label must match the id on the input.

Placeholders are not labels. They disappear when you type. Always use a real <label>.

15.3 Input types

TypeFor
textOne line of text.
emailAn email address.
passwordHidden characters.
numberA number.
telPhone number.
dateDate picker.
checkboxMany choices possible.
radioOnly one choice.
fileUpload a file.

15.4 Other controls

TagWhat it does
<textarea>Multi-line text box.
<select>Drop-down menu.
<fieldset> + <legend>Groups fields with a caption.
<button>Always set type="submit" or type="button".

15.5 A full example

<form action="/register" method="post">
    <fieldset>
        <legend>Your details</legend>

        <p>
            <label for="name">Full name</label>
            <input id="name" name="name" type="text" required>
        </p>

        <p>
            <label for="email">Email</label>
            <input id="email" name="email" type="email" required>
        </p>
    </fieldset>

    <button type="submit">Register</button>
</form>

Try it

Build a form with a name and an email. Click the label "Full name" — the input should get focused. If it does not, the for and id do not match. Then type a bad email and press the button — the browser shows its own error.

Module 16: Checking Input and Staying Safe

Think of it like this: the browser check is a friendly doorman. The server check is a strong lock on the door. You need both — but only the lock really protects you.

16.1 Two levels of checking

  • In the browser — instant feedback, but anyone can bypass it.
  • On the server — the only check you can trust. Always recheck everything there.

16.2 Simple browser checks

<input type="email" required>
<input type="number" min="16" max="120">
<input type="text" required minlength="2">

The browser will not submit the form if these rules are broken.

16.3 XSS — the biggest beginner danger

XSS means someone typed JavaScript into your page — and your page ran it. It can steal data or do things as if it were the user. 
// DANGEROUS
output.innerHTML = userInput;

// SAFE
output.textContent = userInput;

Use textContent for anything from a stranger. It shows the characters as plain text.

16.4 Other risks to know

RiskMeaningFix
CSRFA tricked browser sends a request to your site.CSRF tokens, SameSite cookies.
SQL injectionInput changes a database query.Parameterised queries.
Broken passwordsWeak or stored in plain text.Hash with bcrypt; rate-limit logins.
Mixed contentHTTPS page loads HTTP files.Use HTTPS everywhere.

16.5 Storage warnings

  • localStorage lasts forever and any script can read it. Never store passwords there.
  • sessionStorage lasts until the tab closes.
  • Cookies can be marked HttpOnly and Secure to be safer.

Try it

Type <strong>hello</strong> into an input. Print the value with textContent first — you see the raw angle brackets. Then try innerHTML — "hello" appears bold. That is exactly the danger.

Module 17: JavaScript Basics

Think of it like this: JavaScript is the brain of the page. HTML gives structure, CSS gives looks, JavaScript gives behaviour — it makes things happen.

17.1 Where to put it

<script src="js/script.js" defer></script>

Put it just before </body>. defer means “run it after the page is ready”.

17.2 Variables

const name = "Martha";   // cannot change
let age = 20;            // can change

Use const by default. Use let only when the value really changes.

17.3 Showing values

console.log("Hello");    // prints to the console (F12 → Console)
alert("Welcome!");       // shows a pop-up

17.4 Data types

TypeExample

undefinedundefined (never set)
object{ name: "Ada" }, arrays

17.5 Operators

10 + 5;      // 15
10 % 3;      // 1  (remainder)

5 == "5";    // true  (loose)

true && false;   // false

!true;           // false

const greeting = `Hello, ${name}!`;

17.6 If / else

const score = 78;

if (score >= 80) {
    console.log("Excellent");
} else if (score >= 60) {
    console.log("Pass");
} else {
    console.log("Needs work");
}

const status = score >= 60 ? "Pass" : "Fail";

Falsy values: false, 0, "", null, undefined, NaN. Everything else is truthy.

17.7 Loops

const courses = ["HTML", "CSS", "JavaScript"];

for (const course of courses) {
    console.log(course);
}

for (let i = 0; i < courses.length; i++) {
    console.log(i, courses[i]);
}

17.8 Functions

    return a + b;
}

17.9 Objects and arrays

17.10 Errors

}

Try it

Open the browser console (F12 → Console). Type 2 + 2 and press Enter. Type console.log("Hello"). You have just run your first two lines of JavaScript.

Module 18: The DOM and Events

Think of it like this: the DOM is a live model of the page that JavaScript can see and change. It is like a list of all the boxes on the page. JavaScript can find a box, change its text, add a new box, or remove one.

18.1 Finding elements

const button = document.querySelector("#greetButton");
const allCards = document.querySelectorAll(".card");

querySelector takes any CSS selector and returns the first match.

18.2 Changing content

const message = document.querySelector("#message");
message.textContent = "Updated text";       // safe
message.classList.add("highlight");         // add a CSS class
message.classList.toggle("active");         // on / off

18.3 Creating and removing

const list = document.querySelector("#list");
const item = document.createElement("li");
item.textContent = "New item";
list.appendChild(item);

// item.remove();

18.4 Events

An event is something that happens — a click, a keypress. You listen for events and react to them.

const button = document.querySelector("#greetButton");
const output = document.querySelector("#output");

button.addEventListener("click", () => {
    output.textContent = "Welcome!";
});

18.5 Common events

EventWhen it fires
clickThe user clicks.
inputThe user types in an input.
submitThe user submits a form.
focus / blurThe input gets or loses focus.

18.6 preventDefault

form.addEventListener("submit", (event) => {
    event.preventDefault();   // stop the page from reloading
});

18.7 A full example

const form = document.querySelector("#greetingForm");
const nameInput = document.querySelector("#nameInput");
const result = document.querySelector("#result");

form.addEventListener("submit", (event) => {
    event.preventDefault();
    const name = nameInput.value.trim();

    if (name.length < 2) {
        result.textContent = "Please type at least two letters.";
        return;
    }
    result.textContent = `Hello, ${name}!`;
    localStorage.setItem("userName", name);
});

Try it

Add a button and a paragraph to a page. Use the click example above. Click the button. If nothing happens, open the console — the error message will point at a typo.

Module 19: Accessibility

Think of it like this: accessibility means everyone can use your page — including people who cannot see, cannot hear, or cannot use a mouse. It is not an extra feature. It is a basic kindness, and often a legal requirement.

19.1 The four principles (POUR)

PrincipleMeaning
PerceivableEveryone can see or hear the content.
OperableEveryone can use the controls.
UnderstandableThe content makes sense.
RobustWorks with current and future tools.

19.2 A practical checklist

  • Alt text on informative images; alt="" on decorative ones.
  • A visible label on every form field.
  • Headings in order: one h1, then h2, then h3.
  • Everything reachable with the Tab key.
  • A visible focus ring on links and buttons.
  • Good contrast between text and background.
  • Never rely on colour alone to say something.
  • A "Skip to main content" link at the top.
  • Descriptive link text: "Read the rules", not "click here".
  • Captions for video, transcripts for audio.

19.3 The skip link

<a class="skip-link" href="#main">Skip to main content</a>
...
<main id="main"> ... </main>

.skip-link {
    position: absolute;
    left: -9999px;
}
.skip-link:focus {
    left: 1rem;
    top: 1rem;
    background: #fff;
    padding: .5rem 1rem;
}

19.4 Focus

  • Only one element has focus at a time. Tab moves focus in the order of the HTML.
  • Never write outline: none without giving another visible focus style.

19.5 Testing

  • Automated: Lighthouse, axe DevTools.
  • Keyboard only: unplug the mouse, use Tab.
  • Screen reader: NVDA on Windows, VoiceOver on Mac.
  • Zoom: try 200% and 400%.

Try it

Open your page. Do not touch the mouse. Press Tab many times. Every link and button should show a visible ring. If focus "disappears", an element has outline: none.

Module 20: SEO, Good Design, and Speed

Think of it like this: SEO is how you help search engines find and describe your page. Good design is how you help people use it. Speed is how you keep them from leaving.

20.1 SEO basics

Search engines read your page and decide what it is about. Help them:

  • Unique <title> on every page, 50–60 characters.
  • Meta description, 120–160 characters.
  • One <h1> with clear <h2> sections.
  • Descriptive link text.
  • Meaningful URLs like /courses/web-design.
  • Alt text on images.
  • Semantic HTML so crawlers know what is content.
<title>Computer Science Programmes | BCU</title>
<meta name="description" content="Programmes, activities, and admission information.">

20.2 UX — good design

  • Consistency: same fonts and colours everywhere.
  • Hierarchy: what matters most is biggest and brightest.
  • Whitespace: do not fill every pixel.
  • Clarity: buttons look clickable; links look like links.
  • Feedback: every click should produce a visible change.
  • Helpful errors: say what went wrong and how to fix it.

20.3 Speed

Slow pages lose visitors. Google measures three things:

MetricMeasuresGood score
LCPWhen the main content appears2.5 s or less
INPHow fast the page responds200 ms or less
CLSWhether content jumps around0.1 or less

Easy speed wins

  • Compress images. A 3 MB photo can usually be 200 KB.
  • Always set width and height on images.
  • Use loading="lazy" on images below the fold.
  • Load scripts with defer.
  • Use WebP or AVIF instead of large JPGs.

Try it

Open any page. F12 → Lighthouse → run the report. Pick one issue it finds and fix it. Re-run to see your score go up.

Module 21: Git and Publishing

Think of it like this: Git is an undo history for your whole project. Every save is a snapshot you can go back to. GitHub is a website that stores those snapshots online, and can even publish your site for free.

21.1 Key words

WordWhat it means
RepositoryYour project folder, tracked by Git.
CommitOne saved snapshot with a message.
BranchA separate line of work.
RemoteA copy of the repo on GitHub.
MergeCombine two branches.

21.2 Commands to know

git init                            # start tracking
git status                          # what has changed
git add .                           # stage everything
git commit -m "First version"       # save a snapshot
git push                            # upload to GitHub
git pull                            # get others' changes

21.3 Publish with GitHub Pages

  1. Create a free GitHub account.
  2. Make a new repository and upload your files.
  3. Open Settings → Pages.
  4. Choose the main branch.
  5. Your site is live at https://yourname.github.io/repo-name/.

21.4 Before you publish

  • All links work.
  • No broken images.
  • No passwords or API keys in the files.
  • Works on a phone width.

Try it

Upload one of your pages to GitHub Pages and share the link with a friend. Having a live URL is one of the most motivating moments in web design.

Module 22: Testing Your Website

Think of it like this: testing is like checking your bag before you leave the house — keys, wallet, phone. Simple checks catch most problems.

22.1 Three panels you must know

PanelWhat it does
ElementsSee and edit HTML and CSS live.
ConsoleRead JavaScript errors. First place to look when broken.
NetworkSee every file the page asks for. Red rows are missing files.

22.2 Testing checklist

  • Every link goes somewhere.
  • Every image loads, or has good alt text.
  • Console has no red errors.
  • Page looks OK at 320px, 768px, and 1440px.
  • Every form field has a label.
  • You can reach every button with Tab.
  • The HTML is valid (validator.w3.org).

22.3 When something is broken

  1. Read the error in the Console carefully.
  2. Change one thing.
  3. Reload.
  4. If still broken, change one more thing.

Changing many things at once hides the real cause.

Try it

Open your page. F12 → Console. If it is empty, good — nothing is broken. Now break something on purpose (delete a closing </p>) and reload. You will start to recognise the errors.

Module 23: Practice Projects

You learn to build by building. Do these in order.

Appendix D: How to Start

Beginners often ask: "where do I actually begin?" Here is the answer.

D.1 The short answer

Start with one page, in one folder, using three files. Do it this week. Not after a course. Not after you understand everything. Now.

HTML first — give the page structure.
CSS second — make it look right.
JavaScript third — make it react.

D.2 What you need on day one

ToolWhat to use
Text editorVS Code (free), or even Notepad
BrowserChrome, Firefox, Edge, or Safari
FolderOne called my-website
Something to publish toGitHub Pages (free)

That is all. No paid courses. No frameworks. No MacBook.

D.3 Your first 30 minutes

Do this now, in order

  1. Make a folder called my-website.
  2. Open your text editor. Create a new file.
  3. Type (do not copy) this:
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>My First Page</title>
</head>
<body>
    <h1>Hello, I am learning web design</h1>
    <p>This is my first paragraph.</p>
</body>
</html>
  1. Save it as index.html inside your folder. Use "All Files", not .txt.
  2. Double-click it. It opens in your browser.
  3. Change the text in the <h1>, save, press F5. The page updates.
  4. Change the text in the <title> and reload. The tab changes, the page does not.
  5. Press F12 → Console. Type document.title and press Enter.

That is the whole loop: write → save → reload → inspect.

D.4 Three traps to avoid

  1. Watching too many videos. Watching feels like learning. It is not. For every hour you watch, spend two hours building.
  2. Starting with a framework. React, Bootstrap, and Tailwind all assume you already know HTML, CSS, and JavaScript.
  3. Memorising everything. You will forget. That is fine. Keep MDN open in a tab.

D.5 Where to study

  • MDN Web Docs — the reference.
  • freeCodeCamp — free structured lessons.
  • The Odin Project — free, more demanding.
  • CSS-Tricks — clear layout explanations.
  • web.dev — performance and modern CSS.

D.7 Milestones

Tick each one. They are ordered.

  • ☐ I can write an index.html from memory.
  • ☐ I can link a stylesheet and see the colours change.
  • ☐ I can explain the difference between <head> and <body>.
  • ☐ I can style an element by class.
  • ☐ I can make a box with padding and margin.
  • ☐ I can make a three-column grid.
  • ☐ I can build a form with labels.
  • ☐ I can make a button do something with JavaScript.
  • ☐ I can find a broken link with DevTools.
  • ☐ I have published something on the internet.
The last word: your first page will look plain. Your tenth will be better. The gap between them is not talent — it is the number of times you pressed F12 and asked "why is that happening?". Start today. Start small. Finish something.
